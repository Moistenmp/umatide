Status + audit: we are in testing stage and have not absorbed the community toolchain

Triggered by a reproduction session (2026-10-07) that restored a working environment and then
audited our own position against the CURRENT toolchain. Two facts forced this revision:

1. We had been running an outdated build (compiler + addon dated 2026-09-30). The current release
   ships an operator we did not know about -- `Import Game Unit Nodes` -- which imports every
   non-mesh node of a game unit, named and placed like the game's, including hash-only nodes.
   That is, as a button, what three of our documents describe as hard manual work.
2. Our own asset fails the newer addon's parser (`BONES LOD table is invalid`), consistent with
   the compiler having called our unit `invalid`. So the asset these docs describe is not
   well-formed by the toolchain's own standards.

## README.md
- New section 0: explicit disclaimer -- testing stage, toolchain not fully absorbed, the two
  concrete facts above, and "where a statement here conflicts with the current toolchain's
  behaviour, the toolchain is right".
- New section 0.1: honest placement table. What the community toolchain already covers
  (import/bone names/scene nodes, hiding the vanilla character, effects/particles/shaders/
  dangle/visibility groups) versus what is genuinely left (keeping the model's own proportions,
  and contact points under that constraint). One-line placement: the toolchain solves
  "get a model in"; these docs are only about "get a model in WITHOUT adopting the game's
  proportions" -- and on that road we have one working correction and one open problem.

## docs/02-skeleton-completeness.md
- New section 7: the machine-generated ground truth. Against the human third-person base unit
  with a full limn extract: 245 non-mesh nodes (185 named, 60 hash-only), our name table 228,
  we have 66 and LACK 119 -- listed by family, with the full missing-family table.
- Records two things hand-enumeration got wrong: the `c_*` and `fx_*` node families we never
  listed, and that `j_*forearmroll` existed in the model with only its NAME missing.
- Recommended procedure: run `Import Game Unit Nodes` and diff its output against your own name
  table -- the diff IS the feature list.
- Records the parser caveat (our `.bones` is rejected as `BONES LOD table is invalid`).

## docs/06-toolchain-landscape.md
