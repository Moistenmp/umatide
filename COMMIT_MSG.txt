Docs: add the skin.joints <= 256 budget, the fx_ node family, and three methodological falsifications

Source: a full reproduction session on 2026-10-07 that restored the working environment
(character replaced, vanilla hidden globally, ground snap active) and then measured the gaps.

## 02-skeleton-completeness.md
- New §2.1b: the `fx_` family (muzzle flash from `fx_muzzle_01`, shells from `fx_eject`).
  The compiler README lists THREE node categories a replacement must carry; we had only
  enumerated two and this one was entirely absent from our first patch-up pass.
- New §5.1: the hard limit that decides the whole plan — vertex joint indices are UBYTE4,
  so `skin.joints <= 256`. Measured at the official compiler: 256 => `valid` + `9 skinned`
  + all added names preserved; 408 => `0 skinned` (geometry detached and baked static).
  Also records that of our 225 base slots only 198 are mesh-referenced, and that 27 of the
  rest are NOT padding (foot/grip/face/cloth bones) — dropping them removes exactly what the
  foot and hand systems need.
- Points to the addon's `Import Game Unit Nodes` as the authoritative way to get all three
  families at once, including hash-only nodes (`#1234abcd`) that must be left alone.

## 03-falsified-paths.md
- New §H.1: a name lookup that silently returns every frame. The ground-snap step resolved its
  frame by name (`mf_root`); our asset's root carries a hash name, so it returned early on
  every frame — `生效 0 / 跳过 4440` while the main switch printed `rt2=true`. Symptom was
  feet floating ~0.18 m. Fix: resolve structurally via `Unit.scene_graph_parent`.
- New rows in §I: deciding a composition order from a read-back alone; trusting an offline
  tree interpretation over a known-good constant (cost: a 2822 m correction); treating
  "the compiler said valid" as "the geometry is right" (cost: 26 vertex groups bound to the
  wrong bones). Each carries the measured consequence and the gate that would have caught it.

No game assets, no decompiled source, no model assets are touched.
